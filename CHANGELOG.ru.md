## [0.11.0] - 2026-09-19

### Изменено
- **Переработана верхняя панель просмотра расшаренного артефакта (`/s/:token`)**: теперь это одна строка (логотип, название, бейдж типа, версия/дата/автор/команда) с действиями справа. Размер, число просмотров, срок жизни, комментарий к версии и описание вынесены в блок деталей, который свёрнут по умолчанию и раскрывается шевроном (только для менеджеров; выбор запоминается). «Download source» и «Open in workspace» при наличии обоих собраны в меню «⋯». Выбор версии и видимость стали компактными чипами с иконками, а раскладка остаётся в одну строку вплоть до ширины телефона.
- **Видимость применяется по клику.** Контрол — список строк «Team only / Password protected / Public» с пояснением у каждой: выбор сохраняется сразу (спиннер, затем галочка), панель обновляется на месте и страница больше не перезагружается — артефакт сохраняет прокрутку и состояние. «Password protected» раскрывает поле пароля с кнопкой «Set password» (работает и Enter). Режим, запрещённый настройками команды, показывается неактивным с причиной.
- Поповеры закрываются по Escape и клику вне, возвращают фокус на свой триггер, поддерживают стрелки / Home / End в списке видимости и озвучивают результат для скринридеров.
- Блок деталей по умолчанию свёрнут; его состояние хранится под новым ключом `oa.viewer.details` (старый `oa.viewer.panelCollapsed` игнорируется).

### Исправлено
- **Контрол видимости «ничего не делал».** У панели были `max-height: 40vh; overflow-y: auto`, из-за чего поповер обрезался и кнопка «Apply» оказывалась недоступной, а выбор в `<select>` лишь показывал поле пароля и ничего не сохранял. Выбор версии обрезался так же. Теперь поповеры привязаны к своему триггеру и панелью не обрезаются.

## [0.10.0] - 2026-09-18

### Добавлено
- **Режим конструктора (`build.mjs`)**: Декларативный блочный сборщик HTML-артефактов, встроенный прямо в агентский скилл (`skills/open-artifacts/constructor/`). Агентам больше не нужно писать громоздкий, повторяющийся HTML/CSS-код. Вместо этого они формируют компактное описание структуры в YAML или JSON, которое компилируется в автономный, адаптивный, готовый к тёмной теме HTML за доли секунды.
- **Экономия ~80% токенов и скорость генерации**: Декларативное описание блоков требует примерно на 80% меньше токенов по сравнению с генерацией сырого HTML, кардинально снижает задержку генерации, расходы на токены и исключает ошибки вёрстки.
- **Каталог из 23 модульных блоков**:
  - Данные и метрики: `kpi-row` (адаптивные плитки метрик с трендами и дельтами), `stats-grid` (карточки ключевых показателей), `table` (таблицы с полосатыми строками и клиентской сортировкой по колонкам).
  - Визуализация: `chart-bar`, `chart-line`, `chart-pie` (адаптивные диаграммы Chart.js с автоподстройкой под палитру темы и тёмный режим), `mermaid-diagram` (блок-схемы и диаграммы Mermaid.js).
  - Структура и навигация: `hero` (заголовочные баннеры), `two-columns` (двухколоночные макеты с настраиваемыми пропорциями), `tabs` (доступные вкладки с авто-перерисовкой скрытых графиков и схем), `divider`, `spacer`.
  - Контент: `text-section`, `alert` (плашки `info`, `warning`, `error`, `success`), `timeline` (хронология этапов со статусами), `progress-bars`, `list-cards`, `badge-row`, `code-block` (блоки кода с подсветкой синтаксиса).
  - Медиа: `image` с авто-инлайнингом локальных файлов в base64, подписями и опцией полноэкранного увеличения (`zoomable: true`).
  - Escape-hatch: блок `raw` для произвольного HTML, инлайнового CSS (с доступом к переменным активной темы) и JS-скриптов.
- **Публикация готовых Markdown-отчётов**: Три удобных сценария публикации готовых отчётов:
  - *Режим Passthrough* (`source: report.md`): превращает готовый Markdown-файл напрямую в оформленный артефакт.
  - *Блок `markdown-file`*: вставляет локальный Markdown-файл под KPI-плитками или баннером.
  - *Блок `markdown`*: вставляет Markdown-текст прямо в YAML-спецификацию.
  - Автоматическое удаление YAML frontmatter (`---...---`).
- **5 независимых CSS-тем**: Стили вынесены в отдельные темы (`default`, `data`, `document`, `promo`, `diagram`) и переключаются одной строкой.
- **Сборка и публикация в одну команду**: Поддержка флагов `--push`, `--share`, `--lifetime`, `--org` прямо в сборщике: `node constructor/build.mjs report.yaml --share`.
- **Валидация спецификаций и поддержка привычных синонимов (Model-friendly Aliases)**: В сборщик `build.mjs` добавлена проверка схемы перед сборкой, семантический контроль наполненности (предотвращает silent failures и публикацию пустых блоков), детекция опечаток с подсказками "Did you mean?", а также авто-нормализация привычных для LLM названий полей (`variant` → `kind`, `text`/`content` → `body`, `headers` → `columns`, `code` → `definition`, списки строк в `badge-row` и т.д.). Поддерживаются флаги `--strict` и `--lenient`.

## [0.9.0] - 2026-09-14

### Добавлено
- Опубликован рекламный сайт **https://emaxe.github.io/open-artifacts/** — собран из нового пакета `apps/landing`, разворачивается через `.github/workflows/landing.yml` при каждом изменении в `apps/landing/**`. Чисто информационный, без формы входа/регистрации — кнопки ведут на GitHub и к инструкции self-host.
- В верхней панели публичного вьюера (`/s/:token`) теперь есть маленький логотип со ссылкой на главную страницу приложения, а тем, у кого есть права на управление артефактом (владелец, owner/admin команды или суперадмин), доступен селект «Visibility» — смена режима доступа уже существующей ссылки (только команда / по паролю / публичная) на месте, без отзыва ссылки и выдачи нового URL. На бэкенде — новый `PATCH /api/v1/shares/:id`.

### Изменено
- `/` теперь двухпанельный экран входа/регистрации (форма слева, анимированная брендовая панель справа — повтор терминала, живой демо-артефакт; на узких экранах — одна колонка) вместо прежнего рекламного лендинга. Двуязычный (RU/EN), как и раньше.
- `/login` и `/register` теперь показывают тот же экран вместо отдельных страниц; оба по-прежнему учитывают `?next=` и `?invite=` в точности как раньше, включая возврат на закрытый расшаренный артефакт после входа.

### Удалено
- Встроенный в приложение рекламный лендинг (`pages/landing/`) — его содержимое переехало в `apps/landing` и публикуется отдельно (см. «Добавлено»). `/welcome` теперь редиректит на `/` — для старых закладок и ссылок.

## [0.8.0] - 2026-09-13

### Добавлено
- Двуязычная (RU/EN) рекламная стартовая страница на `/` со встроенной формой входа/регистрации — теперь можно зарегистрироваться или войти, не покидая её. Авторизованные пользователи, как и раньше, попадают в своё рабочее пространство; та же страница доступна по адресу `/welcome`. Новый неаутентифицированный эндпоинт `GET /api/v1/instance/config` сообщает странице (и в будущем — другим страницам), открыта ли самостоятельная регистрация, доступна ли она только по приглашению или закрыта, чтобы форма никогда не рекламировала регистрацию, которая всегда завершится ошибкой 403.
- Таблица «Шаринг» в детальной странице артефакта теперь позволяет дать ссылке название: необязательное поле `label`, видимое только создателю (никогда — посетителю `/s/:token`), в `POST /artifacts/:id/shares` (и в MCP-инструменте `create_share`) — так несколько ссылок на один артефакт можно различить с первого взгляда.
- Любую активную ссылку в таблице «Шаринг» теперь можно скопировать повторно в любой момент кнопкой «Ссылка», а не только сразу после создания — эндпоинт списка ссылок теперь возвращает полный URL каждой ссылки.
- Три отдельные кнопки создания ссылки заменены единым диалогом «Создать ссылку» (режим доступа, необязательное название, пароль — если применимо), кнопка подтверждения которого показывает индикатор загрузки на время создания ссылки, вместо того чтобы на мгновение выглядеть неотвечающей.

### Исправлено
- `incrementShareViewCount` обновлял счётчик просмотров ссылки через чтение-и-запись вместо атомарного SQL-инкремента, из-за чего при одновременных просмотрах единицы терялись. Теперь это один атомарный `UPDATE ... SET view_count = view_count + 1`.
- Правило прокси dev-сервера веба для страниц шаринга (`"/s"`) было простым совпадением по префиксу и незаметно перехватывало любой путь, начинающийся на «s» — включая весь `/src/*`, из-за чего `pnpm dev:web` вместо живых модулей отдавал устаревшую production-сборку. Сужено до `"/s/"`.

### Изменено
- Собственный просмотр ссылки менеджером (владельцем, владельцем/админом команды, суперадмином) снова учитывается — отдельным счётчиком `managerViewCount`. Таблица «Шаринг» теперь показывает и «Просмотры» (только аудитория, без изменений с 0.6.0), и «Всего» (аудитория + менеджер), вместо того чтобы собственная проверка ссылки менеджером выглядела как «вообще не считается».

## [0.7.1] - 2026-09-13

### Исправлено
- Прикреплённые к артефакту файлы (картинки, текстовые и любые другие), встроенные в содержимое самого артефакта (`<img src>`, ссылки и т.д.), не загружались и не открывались при просмотре через песочницу превью/embed-iframe (`/api/v1/artifacts/:id/preview`, `/embed/:token`) — хотя та же самая ссылка `/af/:token`, открытая напрямую в отдельной вкладке, работала корректно. Причины две: `assetOrigin`, который нужен Content-Security-Policy артефакта, чтобы разрешить `media-src`/`font-src` с origin, раздающего файлы, ни в одном из маршрутов реально не передавался; а у обоих sandbox-iframe отсутствовал токен `allow-downloads`, без которого браузер блокирует любое скачивание файла, инициированное изнутри sandbox-фрейма (любой не-inline тип — не картинка/видео/аудио/шрифт — всегда отдаётся с `Content-Disposition: attachment`).

## [0.7.0] - 2026-09-13

### Добавлено
- **Фирменный стиль**: логотип Open Artifacts теперь на страницах входа/регистрации (с отдельным вариантом надписи для тёмной темы), в сайдбаре и мобильной шапке, а также в качестве favicon/apple-touch-icon браузера. Все изображения сгенерированы из одного исходника скриптом `scripts/gen-brand-assets.sh` (ImageMagick), который тоже лежит в репозитории — для воспроизводимости.
- **S3-совместимое хранилище файлов для артефактов**: теперь к артефакту можно загружать и прикреплять картинки и другие файлы — `POST /api/v1/artifacts/:id/files` (`multipart/form-data`), `GET .../files` для списка, `DELETE .../files/:fileId` для удаления, раздача через `GET /af/:token` (прокси приложения, никогда не публичный бакет, presigned-ссылки не выдаются). В CLI — `oa files upload|ls|rm`; в MCP — инструменты `list_artifact_files`/`delete_artifact_file` (сама загрузка доступна только через CLI/REST — вызовы MCP-инструментов текстовые/JSON, а не multipart). Файл всегда принадлежит ровно одному артефакту и удаляется вместе с ним (явное удаление, истечение срока жизни или удаление всей команды ставят его объект в очередь на удаление); файл без артефакта существовать не может. `docker-compose.yml` теперь включает сервис MinIO как хранилище по умолчанию; чтобы использовать внешний S3/R2/Spaces, задайте `S3_ENDPOINT`/`S3_BUCKET`/`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`, а если оставить `S3_BUCKET` пустым — функция полностью выключается (загрузка отвечает `501`, всё остальное работает как прежде).
- **Квоты хранилища на уровне инстанса и команды**: два новых лимита — суммарный объём на команду и объём на один артефакт (в обоих случаях считаются вместе исходник артефакта и загруженные файлы), настраиваются на уровне инстанса в `/admin/settings` и отдельно для каждой команды в её настройках (квоту на артефакт может менять владелец/админ команды, квоту на всю команду — только суперадмин, как и с другими настройками уровня организации). Значение команды может быть только строже инстанс-лимита, но не мягче. **По умолчанию — без ограничений на обоих уровнях** (см. «Изменено» ниже).
- `GET /api/v1/quota` (а также MCP-инструмент `get_storage_quota` и команда CLI `oa quota`): позволяет агенту проверить оставшуюся квоту — на всю команду или для конкретного артефакта — прежде чем решать, загружать ли файл, вместо того чтобы грузить вслепую и потом разбираться с отказом.
- Ошибка `quota_exceeded` теперь структурирована (`scope`, `limitBytes`, `usedBytes`) вместо плоского текстового сообщения — и в REST API, и в MCP-инструментах, чтобы вызывающая сторона могла принять решение, а не просто показать текст.

### Изменено
- **Ломающее изменение**: квота хранилища команды теперь по умолчанию **не ограничена** вместо 1 ГиБ. Команда, чью квоту суперадмин никогда явно не менял (то есть она всё ещё равна старому значению по умолчанию — ровно 1 ГиБ), при миграции переводится на «наследовать квоту инстанса» (которая сама по умолчанию не ограничена); команда, для которой суперадмин осознанно задал конкретное число, сохраняет это число. Колонка `orgs.storageQuotaBytes` стала необязательной (`null` = наследовать) и сменила тип с `integer` на `bigint`, поскольку теперь считает ещё и байты загруженных файлов, а не только исходник артефакта.
- Исправлена скрытая ошибка в настройке инстанса «максимальный размер артефакта» (`InstanceSettings.maxArtifactSizeBytes`): она редактировалась в админке и принималась `PATCH /admin/settings`, но нигде не читалась обратно — ограничение размера артефакта всегда применяло зашитую константу 5 МиБ. Теперь это обязательный, явно разрешаемый параметр на каждом пути создания/обновления артефакта — по тому же паттерну, что уже применяется для срока жизни артефакта.

### Исправлено
- Кнопки «копировать» молча ничего не делали на небезопасном (обычный HTTP) origin или там, где браузер/встраивающая страница запрещали `navigator.clipboard` — в этих случаях API либо не определён, либо отклоняет вызов без видимой ошибки. Добавлен общий хелпер `copyToClipboard()` с фолбэком на `execCommand('copy')`, используется в `CopyButton` и во встроенном скрипте копирования ссылки на публичной странице шаринга.

## [0.6.0] - 2026-09-13

### Добавлено
- **Панель управления на публичной странице шаринга (`/s/:token`)**: шапка над встроенным артефактом показывает каждому посетителю его название, тип, номер отображаемой версии и дату этой версии. Залогиненный участник команды-владельца дополнительно видит автора и название команды; владелец артефакта, владелец/админ команды или суперадмин получают полную панель — описание, размер, срок жизни, счётчик просмотров ссылки, сообщение версии и переключатель версий для просмотра более старых (только просмотр через `?v=N`; ничего не пишет в базу и не меняет то, что видят по этой же ссылке остальные). Панель сворачивается (состояние запоминается в браузере) и скрыта при печати. «Copy link» (всегда копирует канонический URL, без `?v=`) и «Download source» доступны всем, включая анонимных посетителей; «Open in workspace» показывается, если у зрителя есть доступ на чтение к артефакту.
- Новый эндпоинт `GET /s/:token/download` — исходник артефакта, отдаваемый как `text/plain` (никогда не как `text/html` или `image/svg+xml`, независимо от `kind` артефакта) с `Content-Disposition: attachment`, чтобы собственный скрипт `html`/`svg`-артефакта не мог выполниться в origin приложения.
- **Дизайн-шаблоны для `html`-артефактов**: четыре тематические дизайн-системы (`references/design/DESIGN-data.md`, `DESIGN-document.md`, `DESIGN-promo.md`, `DESIGN-diagram.md`) и общая основа `DESIGN-core.md` (токены, светлая/тёмная тема, адаптивность, печать, доступность, чек-лист перед публикацией) внутри `skills/open-artifacts/`. `SKILL.md` теперь направляет агента к подходящему шаблону до того, как он начнёт писать разметку.

### Изменено
- **Ломающее изменение**: просмотр `/embed/:token` тем, кто может управлять артефактом (владелец, владелец/админ команды или суперадмин), больше не увеличивает счётчик просмотров ссылки — просмотр собственной истории версий больше не накручивает метрику, которая должна измерять аудиторию. Для анонимных и прочих залогиненных посетителей счётчик работает как раньше.
- `/s/:token` теперь отдаёт `Cache-Control: private, no-store` и `Vary: Cookie` — ответ теперь зависит от того, кто смотрит (панель различается по аудитории), поэтому его нельзя отдавать из общего кэша не тому посетителю.
- Публичная страница шаринга теперь раскрывает название, тип артефакта, номер отображаемой версии и дату этой версии всем, у кого есть ссылка — раньше страница не несла никаких метаданных, только встроенное содержимое.
- **Серверный рендер `markdown`/`mermaid`/`svg`-артефактов теперь использует полноценные стили** (`apps/api/src/views/artifact-styles.ts`) вместо пятистрочной заглушки: полная типографская шкала, таблицы, блоки кода, цитаты, светлая/тёмная тема через `prefers-color-scheme`, стили печати. Диаграммы `mermaid` теперь выбирают тему (`dark`/`default`) по тому же сигналу, а не всегда рендерятся светлыми.

## [0.5.0] - 2026-09-13

### Добавлено
- **Ссылки только для команды (режим `team`)**: третий режим шаринга наряду с `public` и `password` — ссылка `/s/:token`, которая открывается только залогиненным участникам команды артефакта (любая роль). Пароль не нужен; такую ссылку безопасно кидать в чат команды. Анонимный посетитель перенаправляется на `/login?next=...`; залогиненный, но не участник команды, видит страницу 403 со ссылкой войти под другим аккаунтом.
- **Политика ссылок на уровне команды**: владелец/админ команды (в том числе для своего личного основного воркспейса) теперь может задать в `/t/:orgId/settings` **режим ссылки по умолчанию** (`team` или `public`), используемый при создании ссылки без явного указания режима, и разрешены ли **публичные ссылки** вообще. Запрет действует только на новые ссылки — уже существующие публичные продолжают работать, пока их не отозвать: по одной со страницы артефакта или все сразу (с диалогом подтверждения и счётчиком) из настроек команды.
- **Политика ссылок на уровне инстанса**: суперадмин задаёт те же два параметра на весь инстанс в `/admin/settings`. Команда может быть только строже инстанса, но не мягче: она не может снова разрешить публичные ссылки, запрещённые на инстансе, и не может сделать `public` режимом по умолчанию, пока публичные ссылки запрещены.
- Новые эндпоинты `GET /orgs/:id/share-policy` (действующая политика и счётчик активных публичных ссылок) и `POST /orgs/:id/shares/revoke-public` (массовый отзыв, идемпотентный).
- Новые флаги CLI `--team` и `--public` для `oa push` и `oa share` наряду с существующим `--password`; обе команды теперь печатают итоговый режим ссылки рядом с URL.

### Изменено
- **Критическое изменение**: `oa push --share` и `oa share <id>` без явного указания режима теперь создают ссылку в **настроенном по умолчанию режиме команды**, а не всегда `public`. Прежнее поведение — явный флаг `--public`.
- **Критическое изменение**: аргумент `mode` у MCP-инструмента `create_share` больше не имеет значения по умолчанию `"public"` — при его отсутствии используется режим команды по умолчанию, как и в CLI. Результат вызова всегда возвращает реально применённый режим.
- **Критическое изменение**: поле `mode` в `POST /artifacts/:id/shares` стало необязательным (при отсутствии берётся режим команды по умолчанию) вместо обязательного; запрос `"public"`, когда это запрещено, теперь возвращает `403 public_shares_forbidden` с `allowedModes` в теле ответа.
- **Критическое изменение**: `POST /s/:token/unlock` для ссылки не в режиме `password` теперь возвращает `400 not_password_mode` вместо молчаливого `{ok:true}`.
- Скилл агента (`skills/open-artifacts/SKILL.md`) больше не предписывает агенту самостоятельно решать вопросы приватности ссылки (по умолчанию не шарить, генерировать пароль, спрашивать перед публикацией) — это решение теперь полностью на стороне политики команды/инстанса выше; скилл лишь описывает три режима и новую ошибку.

### Исправлено
- Ссылка в режиме `password` с `passwordHash = NULL` (состояние, которое не должно возникать, но не было защищено явно) считалась общей матрицей доступа полностью публичной; теперь она корректно по-прежнему требует пароль.
- Параметр `?next=` на странице входа не проверялся и допускал open-redirect; теперь разрешены только относительные пути того же источника.

## [0.4.0] - 2026-09-11

### Добавлено
- **Время жизни артефактов (TTL)**: теперь у артефактов можно задать срок жизни. Суперадмин задаёт в `/admin/settings` максимальное время жизни артефакта на весь инстанс (в минутах; по умолчанию без ограничений) — оно же служит сроком по умолчанию для новых артефактов. Владельцы/админы команды могут задать своё, более строгое ограничение для своей команды, но не мягче инстанс-лимита. При создании (CLI `oa push --lifetime`, веб-интерфейс, поле `lifetime` в REST/MCP API) можно выбрать любой срок в рамках действующего лимита, а также изменить его позже через `PATCH`. По истечении срока содержимое артефакта удаляется безвозвратно (все версии удаляются без возможности восстановления) — остаётся только запись-«надгробие» для аудита и аналитики. Фактическое удаление выполняет фоновая задача (`ARTIFACT_PURGE_INTERVAL_MINUTES`, по умолчанию 5 минут); при чтении просроченный артефакт считается недоступным немедленно, независимо от того, добралась ли до него фоновая задача.

### Изменено
- Уменьшение максимального срока (инстанса или команды) пересчитывает срок жизни уже существующих артефактов от их даты создания (`min(текущий срок, дата создания + новый максимум)`) и может привести к немедленному истечению уже созданных артефактов; увеличение максимума никогда не продлевает уже созданные артефакты.
- `GET /artifacts` и `GET /artifacts/:id` теперь скрывают/возвращают 404 для артефакта с истёкшим сроком жизни, даже до того, как до него доберётся фоновая задача. В данные артефакта добавлено поле `expiresAt`.

## [0.3.0] - 2026-09-11

### Добавлено
- **Личные (привязанные к пользователю) API-ключи**: `oa login` теперь по умолчанию выпускает личный ключ — один вход, действующий во всех ваших командах с вашей реальной ролью в каждой, вместо отдельного ключа агента на команду. `oa orgs` показывает ваши команды и текущую выбранную; `oa use <team>` задаёт команду по умолчанию для текущего проекта (записывается в `.oa.json` без секретов, можно коммитить) или `--global` для всего компьютера. MCP-сервер получил параметр `orgId` у соответствующих инструментов и новый инструмент `list_orgs`; если команда не выбрана и их несколько, вместо угадывания возвращается структурированная ошибка `org_required` со списком. Ключи агентов (`oa login --agent`) не изменились и остаются правильным выбором для CI и узких прав. Новая страница «Настройки → Личные API-ключи» для выпуска и отзыва личных ключей в веб-интерфейсе.
- **Автосоздаваемое основное пространство**: теперь при регистрации каждому пользователю сразу создаётся личное «основное» пространство — в том числе при регистрации по ссылке-приглашению, вместе с членством в пригласившей команде — вместо приземления без единой команды.
- **Полноценный жизненный цикл приглашений**: приглашение теперь настоящая машина состояний (`pending`/`accepted`/`declined`/`revoked`) со списком, отзывом и перевыпуском; публичный превью по ссылке `/invite/:token`; и раздел «Приглашения» (`/invites`) в интерфейсе — уже зарегистрированный приглашённый видит приглашение и сам принимает или отклоняет его, без отправки почты.
- **Идентификация одноимённых команд**: единый компонент `OrgIdentity` (цветная монограмма от id, бейдж «Основное», вторая строка — владелец/slug) применяется везде, где отображается команда, плюс email владельца и счётчики участников/артефактов в каждом списке — теперь две команды (или два личных пространства) с одинаковым названием различимы.
- **Переключатель команд с поиском**: переключатель в сайдбаре теперь всплывающее окно с поиском, сгруппированное на «Основное» / «Мои команды» / (для суперадмина) «Все команды инстанса» с серверным поиском.
- **Переработанная админка**: `/admin` теперь настоящие вкладки-роуты (Обзор, Пользователи, Команды, Аудит, Настройки инстанса) вместо одного компонента на 387 строк; поиск пользователей по имени и email с настоящей пагинацией по `total` и чипами команд; аудит с keyset-пагинацией, резолвнутыми именами/email акторов и русскими подписями действий; все пять настроек инстанса теперь редактируются (раньше — только режим регистрации).
- **Инструкции для агентов — всем пользователям**: шпаргалка по подключению агентов переехала из `/admin/instructions` в `/help/agents`, доступна любому авторизованному — подключение агента задача команды, а не только суперадмина. Старые ссылки продолжают работать через редирект.
- **Дизайн-система на Tailwind v4**: весь веб-интерфейс переведён с рукописного CSS на Tailwind v4 и набор доступных примитивов (`Button`, `Dialog`, `ConfirmDialog`, `DropdownMenu`, `Toast`, `Table`, `EmptyState` и другие), с переключателем светлой/тёмной/системной темы и мобильным выдвижным меню — без единой новой runtime-зависимости.
- **Управление командами**: переименование команды, добавление уже зарегистрированного пользователя напрямую в команду (минуя приглашение), редактор квоты хранилища для суперадмина.

### Изменено
- **`GET /auth/me` больше не отдаёт суперадмину все команды инстанса**: теперь только собственные членства, плюс `mainOrgId` и счётчик ожидающих приглашений — до чужих команд суперадмин теперь добирается поиском. (Ломающее изменение API для внешних клиентов, ожидавших старый формат.)
- Последние оставшиеся нативные диалоги `confirm()`/`alert()`/`prompt()` заменены на полноценные модальные компоненты.

### Исправлено
- **Подмена email при регистрации по приглашению**: регистрация по ссылке больше не доверяет присланному email, если он не совпадает с адресом из приглашения — закрыта дыра, позволявшая присоединиться под произвольным адресом, зная только ссылку.
- Владельца-создателя команды можно было удалить как последнего оставшегося owner через `DELETE /orgs/:id/members/:userId` (гард стоял только на `PATCH`); теперь оба эндпоинта это запрещают, а создатель личного пространства не может покинуть его или быть из него удалён.
- Вход и регистрация больше не ведут на несуществующий маршрут `/artifacts`.
