Self-hosted (автономный) сервис хостинга артефактов для AI-агентов — открытая альтернатива Claude Artifacts. Любой агент (Claude, Cursor, Codex, Windsurf, Antigravity, OpenCode или кастомные LLM-скрипты) авторизуется с помощью токена или OAuth Device Flow, публикует HTML, Markdown, Mermaid-диаграммы или SVG и получает ссылку для интерактивного просмотра человеком в браузере.

Разворачивается в виде единого легковесного стека Docker Compose.

🌐 **Лендинг:** [https://emaxe.github.io/open-artifacts](https://emaxe.github.io/open-artifacts)

## Ключевые возможности

- 🛡️ **Песочница с нулевым доверием (Zero-Trust Sandbox)**: Контент, сгенерированный агентами, отображается в строго изолированных контейнерах `<iframe>` с уникальным origin (`allow-scripts`, без доступа к cookie или `localStorage` хоста, строгая Content Security Policy).
- 🧩 **Режим конструктора (Декларативный сборщик артефактов)**: Быстрая и сверхэкономная по токенам сборка качественных HTML-отчётов. Агенты описывают страницы в виде лаконичных YAML/JSON спецификаций либо подключают готовые Markdown-отчёты с помощью 23 модульных блоков. Компиляция за миллисекунды, сокращение расхода исходящих токенов LLM на ~80% и полное исключение галлюцинаций в верстке и стилях.
- 📦 **Поддержка форматов**: Интерактивные веб-приложения на HTML/JS, разметка Markdown (с синтаксисом GitHub), адаптивные диаграммы Mermaid и векторная графика SVG.
- ⚡ **Встроенный MCP-сервер**: Готовый эндпоинт Model Context Protocol по пути `/mcp` (Streamable HTTP) для бесшовной интеграции с Cursor, Claude Desktop, Claude Code и другими агентами.
- 🤖 **Стандартный AI Agent Skill**: Полная поддержка стандарта `skills.sh` (`npx skills add emaxe/open-artifacts`) с автоматической установкой CLI и авторизацией через Device Flow.
- 🎨 **Встроенные дизайн-системы**: Четыре готовых дизайн-шаблона (дашборды, документы, промо/презентации, диаграммы) идут вместе со скиллом — агент сам выбирает подходящий перед публикацией, поэтому артефакты выглядят единообразно.
- 🔑 **Гибкая аутентификация**: Интерактивная привязка устройств через OAuth Device Flow (`oa login`) и фоновые сервисные токены (`OA_TOKEN`).
- 🖥️ **Двуязычный экран входа**: На `/` неавторизованный посетитель видит двухпанельный экран входа/регистрации (английский/русский, переключатель в шапке) — без рекламного текста на собственном инстансе. Авторизованные посетители сразу попадают в своё рабочее пространство. Рекламная страница продукта живёт отдельно — **[emaxe.github.io/open-artifacts](https://emaxe.github.io/open-artifacts/)** (исходники: `apps/landing/`), опубликована на GitHub Pages и не содержит собственной авторизации.
- 👥 **Организации, команды и роли**: Разделение на организации/команды, управление пользователями, переключатель команд и роли (`superadmin`, `admin`, `member`).
- 🔗 **Управление доступом к ссылкам**: Ссылки только для команды, защита паролем, публичные ссылки (с необязательным названием для собственного удобства) и автоматическое истечение срока действия (1 час, 1 день, 7 дней, 30 дней) — команда и суперадмин управляют режимом по умолчанию и могут полностью запретить публичные ссылки. На каждой странице шаринга есть фирменная панель (название, тип, версия), которая для тех, кто может управлять артефактом, разворачивается в автора, команду и переключатель версий — там же можно сменить режим доступа самой этой ссылки, на месте, без отзыва и выдачи нового URL.
- 🖼️ **Вложенные файлы**: Картинки и другие файлы можно загружать в S3-совместимое хранилище (по умолчанию в `docker-compose.yml` уже есть MinIO) и прикреплять к артефакту — раздача идёт через прокси приложения, бакет никогда не публикуется напрямую. Агент может проверить оставшуюся квоту (`oa quota` или MCP-инструмент `get_storage_quota`) перед загрузкой. Квоты хранилища задаются на инстанс и на команду (на команду и на один артефакт, по умолчанию без ограничений); файлы удаляются автоматически вместе с артефактом.
- 🚀 **Быстрый запуск**: Развертывание в продакшн одной командой с помощью Docker Compose или интерактивного скрипта `./run.sh`.

## Быстрый старт

### Вариант 1: Интерактивный запуск (рекомендуется)

```bash
./run.sh
```

Интерактивное меню для управления всеми сценариями: продакшн (Docker), локальная разработка, сборка, тесты и миграции базы данных.

### Вариант 2: Docker Compose

```bash
cp .env.example .env        # Настройте SESSION_SECRET, SUPERADMIN_EMAIL/PASSWORD
docker compose up -d
```

Откройте `http://localhost:3000`, войдите под учетной записью суперпользователя, указанной в `.env`. Миграции базы данных применяются автоматически при старте контейнера.

## Локальная разработка

Требования: **Node.js 20+**, **pnpm** и **Docker** (для локальной PostgreSQL).

```bash
# 1. Установка зависимостей
pnpm install

# 2. Запуск локального PostgreSQL на localhost:5433
docker compose -f docker-compose.dev.yml up -d

# 3. Применение схемы базы данных
cd apps/api && DATABASE_URL=postgres://postgres:postgres@localhost:5433/open_artifacts_dev \
  pnpm exec drizzle-kit push

# 4. Запуск серверов разработки
pnpm dev:api      # API и MCP сервер на http://localhost:3000
pnpm dev:web      # Веб-интерфейс React на http://localhost:5173 (проксирует /api на :3000)
pnpm dev:landing  # Рекламный сайт на http://localhost:5174 (apps/landing, бэкенд не нужен)
```

Разработка и отладка CLI:
```bash
cd packages/cli && pnpm dev -- login --server http://localhost:3000
```

## Скилл для AI-агентов (Claude, Cursor, Windsurf и др.)

В Open Artifacts встроен навык для агентов по стандарту [skills.sh](https://skills.sh/emaxe/open-artifacts). Он обучает AI-агентов самостоятельно устанавливать CLI `@emaxe/oa`, подключаться к инстансу, публиковать артефакты и возвращать аккуратные ссылки в диалог. Вместе с ним поставляются четыре готовые дизайн-системы — для дашбордов, отчётов, промо/презентаций и диаграмм — и общая основа токенов; агент выбирает подходящую перед тем, как писать `html`-артефакт, поэтому опубликованные артефакты выглядят единообразно независимо от того, какой агент или сессия их создали.

### 1. Установка через skills.sh

```bash
# Для текущего проекта/репозитория (рекомендуется):
npx skills add emaxe/open-artifacts

# Или глобально для всех проектов на машине:
npx skills add emaxe/open-artifacts -g
```

### 2. Подключение агентов

Агенты могут авторизоваться двумя способами:

#### Вариант A: личный доступ (рекомендуется)
1. Выполните в терминале агента:
   ```bash
   oa login --server http://localhost:3000
   ```
2. Утилита выведет одноразовый код активации (например, `ABCD-1234`) и ссылку.
3. Откройте `http://localhost:3000/activate?code=ABCD-1234` в браузере и подтвердите доступ («Разрешить») — выбирать команду здесь не нужно.
4. Выпускается **личный ключ**, действующий во всех командах подтвердившего (с его реальной ролью в каждой), сохраняется в `~/.config/open-artifacts/credentials.json` (права `600`). Выберите команду для конкретного проекта:
   ```bash
   oa orgs           # список ваших команд
   oa use <team>     # команда по умолчанию для этого проекта (пишет .oa.json без секретов, можно коммитить)
   ```

#### Вариант Б: ключ агента, запертый в одной команде (для CI)
Выполните `oa login --agent` (потребуется явно выбрать команду при подтверждении) либо выпустите API-ключ в веб-интерфейсе в разделе **Команда > Агенты** (`/t/:orgId/agents`) и передайте переменные окружения:

```bash
export OA_SERVER="http://localhost:3000"
export OA_TOKEN="oa_live_xxxxxxxxxxxxxxxxxxxxxxxx"
```

Проверка подключения:
```bash
oa whoami
```

### 3. Основные команды CLI

| Задача | Команда |
|---|---|
| Проверить токен, тип ключа и выбранную команду | `oa whoami` |
| Список команд, доступных ключу | `oa orgs` |
| Задать команду по умолчанию для проекта | `oa use <team-slug>` |
| Опубликовать артефакт и получить ссылку в режиме по умолчанию для команды | `oa push report.html --title "Отчет за 3 квартал" --share` |
| Обновить артефакт (новая версия) | `oa push report.html --id <artifact-id> --message "Обновлены цифры"` |
| Создать ссылку только для команды (открывается лишь залогиненным участникам) | `oa share <artifact-id> --team` |
| Поделиться с паролем и сроком жизни 7 дней | `oa share <artifact-id> --password "secret123" --expires 7d` |
| Создать полностью публичную ссылку (может быть запрещено политикой команды/инстанса) | `oa share <artifact-id> --public` |
| Посмотреть список артефактов в текущей команде | `oa list` |
| Скачать содержимое артефакта | `oa get <artifact-id> -o local.html` |
| Удалить артефакт | `oa rm <artifact-id>` |
| Отозвать ссылку на артефакт | `oa unshare <share-id>` |

Поддерживаемые форматы: `html`, `markdown`, `mermaid`, `svg`. Флаг `--json` выводит машиночитаемый JSON для любой команды.

## 🧩 Режим конструктора: Декларативный сборщик артефактов

Генерация чистого HTML/CSS силами AI-агентов имеет серьёзные недостатки:
- **Огромный расход токенов**: от 2 000 до 5 000+ исходящих токенов на каждый артефакт, что сжигает контекстное окно модели и значительно увеличивает стоимость.
- **Высокая задержка**: стриминг тысяч строк повторяющегося HTML-кода занимает от 30 до 60+ секунд.
- **Хрупкая верстка и галлюцинации**: модели часто допускают синтаксические ошибки, ломают CSS, забывают про адаптивность для мобильных экранов, не поддерживают тёмную тему или пытаются подключить внешние шрифты/скрипты, блокируемые строгой CSP-политикой песочницы.

**Режим конструктора (Constructor Mode)** полностью решает эти проблемы. Вместо написания громоздкого HTML-кода агент создаёт компактную структурированную **YAML или JSON-спецификацию**. Встроенный легковесный сборщик (`skills/open-artifacts/constructor/build.mjs`) за миллисекунды компилирует её в автономный, доступный, адаптивный HTML-артефакт с поддержкой тёмной темы.

### Ключевые преимущества

| Преимущество | Чистый HTML | Режим конструктора |
|---|---|---|
| **Расход токенов** | 2 000 – 5 000+ токенов | **~150 – 400 токенов (экономия ~80%)** |
| **Скорость генерации** | 30 – 60+ секунд | **1 – 3 секунды (в 10 раз быстрее)** |
| **Стили и оформление** | Ручная верстка, часто несогласованная | **Продуманные токены дизайн-системы и 5 готовых тем** |
| **Тёмная / Светлая тема** | Часто отсутствует или сломана | **Автоматически через CSS-переменные и связку с темами Chart.js** |
| **CSP песочницы** | Часто блокируется (внешние шрифты, сторонние CDN) | **100% соответствие строгой политике безопасности iframe CSP** |
| **Интерактивные элементы** | Требуют ручного шаблонного JS-кода | **Протестированные блоки: сортируемые таблицы, табы, лайтбокс, графики, диаграммы** |

### Как это работает

```
┌───────────────────────────┐      ┌───────────────────────────────┐      ┌─────────────────────────┐
│  AI-агент                 │      │  Конструктор (build.mjs)      │      │  Сервер Open Artifacts  │
│                           │      │                               │      │                         │
│  Генерирует YAML/JSON     │ ───► │  • Валидирует блоки           │ ───► │  Автономный HTML        │
│  или указывает на .md     │      │  • Встраивает CSS-темы        │      │  Изолированный iframe   │
│  (на ~80% меньше токенов) │      │  • Дедуплицирует CDN-скрипты  │      │  Публичная ссылка       │
└───────────────────────────┘      └───────────────────────────────┘      └─────────────────────────┘
```

#### 1. Сборка и публикация одной командой
```bash
# Собрать и сразу опубликовать с генерацией ссылки:
node skills/open-artifacts/constructor/build.mjs report.yaml --share
```

### 3 способа публикации Markdown-отчётов

Если у вас уже есть готовый Markdown-документ (исследование, RFC, постмортем, отчет об аудите), вам не нужно переписывать его на блоки:

1. **Вариант А — Режим Passthrough (максимальная экономия токенов)**:
   Укажите путь к файлу markdown. Сборщик отрендерит его, применит стили темы `document` и сформирует чистый автономный артефакт. Фронтматтер (`---...---`) удаляется автоматически:
   ```yaml
   title: "Аналитическая записка за Q3"
   theme: document
   source: /path/to/report.md
   ```

2. **Вариант Б — Блок `markdown-file` (Отчёт с шапкой и метриками)**:
   Объедините существующий `.md`-файл с верхнеуровневыми плитками KPI или hero-баннером:
   ```yaml
   title: "Резюме для руководства"
   theme: document
   blocks:
     - type: hero
       title: "Итоги работы за Q3"
     - type: kpi-row
       items: [...]
     - type: divider
       label: "Полный текст отчёта"
     - type: markdown-file
       path: /path/to/report.md
   ```

3. **Вариант В — Блок `markdown` (Встроенный текст)**:
   Встраивайте фрагменты Markdown прямо в YAML-спецификацию:
   ```yaml
   blocks:
     - type: markdown
       content: |
         ## Краткое содержание
         Выручка выросла на **18% кв/кв** благодаря расширению сегмента Enterprise.
   ```

### 5 независимых тем оформления

Темы отделяют визуальный стиль от структуры данных. Переключение темы выполняется в одну строчку в YAML:

- **`default`**: Сбалансированная нейтральная тема для общих документов и смешанных материалов.
- **`data`**: Оптимизирована для аналитических дашбордов, плотных таблиц и метрик.
- **`document`**: Оптимизирована для комфортного чтения больших текстов (ширина 720px, интерлиньяж 1.8).
- **`promo`**: Презентационная тема для анонсов и промо-страниц (градиентный hero, приподнятые карточки).
- **`diagram`**: Центрированный адаптивный макет для архитектурных схем и диаграмм.

## MCP-сервер (Model Context Protocol)

Каждый инстанс Open Artifacts предоставляет встроенный сервер MCP по адресу `<APP_ORIGIN>/mcp` (Streamable HTTP). Подключите любой MCP-клиент, передав API-ключ (личный или агента) в заголовке `Authorization`. Личный ключ действует во всех своих командах — параметр `?orgId=` в URL задаёт команду по умолчанию для этого подключения (не нужен, если у ключа только одна команда):

```json
{
  "mcpServers": {
    "open-artifacts": {
      "url": "http://localhost:3000/mcp?orgId=<team-id>",
      "headers": {
        "Authorization": "Bearer oa_live_xxxxxxxxxxxxxxxxxxxxxxxx"
      }
    }
  }
}
```

### Доступные инструменты MCP
- `whoami`: Информация о токене, scopes и выбранной команде.
- `list_orgs`: Список команд, доступных этой идентичности.
- `list_artifacts`: Поиск и получение списка артефактов команды.
- `get_artifact`: Получение метаданных и содержимого артефакта.
- `create_artifact`: Создание нового артефакта (`html`, `markdown`, `mermaid`, `svg`).
- `update_artifact`: Публикация новой версии существующего артефакта.
- `delete_artifact`: Удаление артефакта в архив.
- `create_share`: Создание ссылки только для команды, защищённой паролем или публичной. Если `mode` не указан, используется режим по умолчанию для команды.
- `list_shares`: Просмотр действующих ссылок артефакта.
- `revoke_share`: Мгновенный отзыв ссылки.

`list_artifacts` и `create_artifact` принимают необязательный параметр `orgId`, переопределяющий команду по умолчанию для подключения. Если он не задан и команд несколько, вместо угадывания возвращается структурированная ошибка `org_required` со списком кандидатов.

## Команды, приглашения и админка

При регистрации каждому пользователю автоматически создаётся личное **основное пространство** (в том числе при регистрации по приглашению — человек оказывается сразу в своём пространстве и в пригласившей команде). Обычные команды создаются явно в разделе **Команды** (`/teams`).

Приглашение в команду (`/t/:orgId/settings`) работает и для новых, и для уже зарегистрированных пользователей:
- **Новый email** — выдаётся одноразовая ссылка (`/invite/:token`), которую нужно отправить самостоятельно; встроенной отправки почты нет.
- **Существующий аккаунт** — приглашение появляется у него в разделе **Приглашения** (`/invites`), и он сам принимает или отклоняет его; никого не добавляют в команду молча.

У суперадминов отдельный раздел `/admin` (Обзор, Пользователи, Команды, Аудит, Настройки инстанса) — отдельно от инструкций по подключению агентов.

|---|---|---|

### Хранилище файлов и квоты

Загруженные файлы (картинки, вложения) хранятся в S3-совместимом бакете и раздаются через прокси
приложения по адресу `/af/<token>` — сам бакет остаётся приватным, прямые ссылки на него никогда не
выдаются. Файл всегда принадлежит ровно одному артефакту и удаляется вместе с ним (мягкое удаление,
истечение срока жизни или удаление всей команды — всё это ставит файлы в очередь на удаление);
файл без артефакта существовать не может.

Квоты хранилища по умолчанию не ограничены — и на команду, и на один артефакт. Суперадмин задаёт
лимиты на весь инстанс в `/admin/settings`; команда может задать своё, более строгое значение (но
не мягче) — квоту на артефакт может менять владелец/админ команды, а квоту на всю команду —
только суперадмин. Перед загрузкой агент может проверить оставшуюся квоту через `GET
/api/v1/quota` (или `oa quota` / MCP-инструмент `get_storage_quota`) и решить, стоит ли грузить
файл.

### Время жизни артефактов (TTL)

По умолчанию артефакты живут бессрочно. Суперадмин может задать в `/admin/settings`
максимальное время жизни артефакта (в минутах) для всего инстанса — оно же становится сроком по
умолчанию для новых артефактов. Владельцы/админы команды могут задать своё, более строгое
ограничение для своей команды, но не мягче общего инстанс-лимита. При создании (CLI `--lifetime`,
веб-интерфейс или поле `lifetime` в API/MCP) можно выбрать любой срок в рамках действующего
лимита, а также изменить его позже.

По истечении срока содержимое артефакта **удаляется безвозвратно** — история версий пропадает
навсегда, остаётся только запись-«надгробие» для аудита и аналитики. Уменьшение максимума
пересчитывает срок уже существующих артефактов от их даты создания (`min(текущий срок, дата
создания + новый максимум)`); увеличение максимума никогда не продлевает уже созданные артефакты.

### Режимы ссылок и политика шаринга

Ссылка бывает трёх режимов: `team` (открывается только залогиненным участникам команды артефакта),
`password` (любой, у кого есть URL и пароль) и `public` (любой, у кого есть URL). Если режим не
указан явно — обычный флаг `--share`, отсутствие поля `mode` в API, вызов `create_share` без
аргумента `mode` — используется настроенный по умолчанию режим команды, а не всегда `public`.

Владелец/админ команды задаёт в **настройках команды** (`/t/:orgId/settings`, включая личный
основной воркспейс) две вещи: **режим ссылки по умолчанию** (`team` или `public`) и **разрешены ли
публичные ссылки вообще**. Суперадмин задаёт те же два параметра на уровне всего инстанса в
`/admin/settings`; команда может быть только строже инстанса, но не мягче — она не может снова
разрешить публичные ссылки, запрещённые на инстансе, и не может сделать `public` режимом по
умолчанию, пока публичные ссылки запрещены. Запрет действует только на новые ссылки; уже
существующие публичные ссылки продолжают работать, пока их не отзовут — по одной со страницы
артефакта или все сразу из настроек команды.

Режим доступа уже существующей ссылки можно поменять и на месте — без отзыва и выдачи нового URL —
прямо на её собственной странице просмотра (`/s/:token`), если у вас есть права на управление
артефактом (`PATCH /api/v1/shares/:id`).
